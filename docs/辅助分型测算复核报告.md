# 核心病种辅助分型测算复核报告

**复核对象**：本地目录测算系统中"核心病种 → 辅助分型（第三步）"全链路
**复核依据**：
- 用户提供的《DIP3.0 辅助分型规则文本》（CCI 四级、触发条件、触发系数、调节系数、恶性 7 亚型 / 非恶性 4 级、年龄分档、ICU 分型）
- 权威数据源 `data/CCI.xlsx`（Charlson 17 项权重字典，231 行）、`data/中重度分型诊断.xlsx`（重度/中度诊断清单，3684 行）
**复核日期**：2026-07-30
**涉及代码**：
- `src/core/auxiliary_directory.py`（`CCICalculator` / `DiseaseSeverityClassifier` / `AgeFeatureClassifier` / `ICUStayClassifier` / `AuxiliaryDirectoryCalculator`）
- `src/core/local_directory_generator.py`（`apply_auxiliary_typing` 及其子方法，约 L1705–1932）
- `src/core/auxiliary_directory_exporter.py`（`AuxiliaryDirectoryExporter`，被 `web/app.py` 调用）
- `src/models/models.py`（`MedicalRecord` / `DiseaseGroup`）

---

## 一、总体结论

**框架正确、细节多处偏离规范，且存在"两套互相矛盾的辅助分型实现"。**

- 四维度（CCI / 严重程度 / 年龄 / ICU）的**分型结构、分级顺序、分档边界**整体符合规范；
- 但**调节系数与触发系数是硬编码经验值，完全没有按规范"mj/M 数据驱动"测算**（核心背离）；
- **CCI 计算把主诊断也计入了**（违反"通过其他诊断判断"）；
- **重度/中度诊断范围、CCI 权重字典均为硬编码，与权威 xlsx 漂移/覆盖不全**，应改为运行时加载；
- 本地目录主流程（`apply_auxiliary_typing`）与 Web 导出路径（`AuxiliaryDirectoryExporter`）**使用两套名称、分档、系数完全不同的实现，结论互相打架**。

建议按"重大 → 中度 → 轻微"顺序整改，优先消除数据正确性与一致性问题。

## 三、偏差清单

### 🔴 重大偏差（必须修正）

#### B1. CCI 把主诊断也计入合并症（违反"其他诊断"原则）
- **规范**："通过病例的**其他诊断**判断所属并发症/合并症类型，将其权重累加"。
- **实现**：`local_directory_generator.py` L1849 `diags = [m['main_diag_code'], m['related_diag_code']]`，主诊断一并进入 `calculate_cci`。
- **影响**：主诊断本身被当合并症计分，CCI 普遍虚高，四级分层失真。
- **整改**：CCI 仅使用其他诊断（次要诊断及附加诊断），剔除主诊断。

#### B2. 调节系数 / 触发系数未数据化，全为硬编码（核心背离）
- **规范**：
  - 触发系数 = 该辅助分型上年度病例平均住院费用 ÷ 该病种上年度平均住院费用；
  - 调节系数 = mj / M（mj=该 j 类辅助分型满足触发条件病例平均住院费用，M=该病种全部病例平均住院费用）；
  - 符合多规则时，纳入触发系数最高的分型。
- **实现**：整套系数（`auxiliary_directory.py` 各处 `coefficient`、各 classifier 返回的 1.0–1.7 固定值）均为**经验硬编码**；"触发系数""mj/M"机制**完全不存在**。`apply_auxiliary_typing` 直接取 `sev['coefficient']` 等作为子组系数。
- **影响**：这是与规范最根本的背离——辅助分型应"基于数据测算调节系数"，当前变成固定加成，无法反映真实费用差异、也无法体现触发系数竞争。
- **整改**：新增测算层——对各辅助子组计算 `mj`（组内平均住院费用）与 `M`（病种全样本平均住院费用），`调节系数 = mj / M`；并按触发系数最高者竞争分流。

#### B3. 权威字典未加载，硬编码与 xlsx 漂移 / 覆盖不全
- **CCI 字典**：`CCI_SCORES` 硬编码 139 个 3 位前缀，与权威 `data/CCI.xlsx`（135 个前缀）对比：
  - **漏 39 个**（如 J45 哮喘、N03–N05 肾炎、I70 动脉硬化、K55 肠血管、M35 结缔组织细分、G30/G45/G46/G83、B18、C76/C7A、E14、H34、I09/I11/I12/I27/I42/I85/I86、J60–J67/J70、K71/K75、Z49/Z94 等）；
  - **多 44 个**（肿瘤细分 C00–C13、艾滋亚码 B20–B23、痴呆细分 F00/F02、心梗细分 I22–I24、脑血管细分 I66/I68/I69、周围血管细分 I73/I74、J41 等）。
  - 注：xlsx 的 component 含"风湿性疾病/偏瘫或截瘫/肾病"，说明标准 Charlson 17 项本就含这些，代码纳入它们**不算错**；真正问题是**应运行时加载 xlsx 而非维护漂移的硬编码快照**。
- **重度/中度诊断范围**：`DiseaseSeverityClassifier._has_severe_complication` (L297–313)、`_has_organ_damage` (L315–330) 硬编码极少码（R57/N17/J96/K72/A40–A41、I20–I25/I60–I69/J85–J86/K80–K87/N10–N17）。而权威 `data/中重度分型诊断.xlsx` 中：
  - 重度诊断 = `DIP_ASSISTANT_TYPE=QTZD` 且 `DIP_ASSISTANT_CODE=2`（**268 条**）；
  - 中度诊断 = `QTZD` 且 `code=1`（**3053 条**）；
  - 硬编码覆盖量不足字典的零头。
- **整改**：`CCICalculator` 改为从 `CCI.xlsx` 加载权重（按 component→权重映射）；`_has_severe_complication` / `_has_organ_damage` 改为从 `中重度分型诊断.xlsx` 加载 code=2 / code=1 的诊断码集（QTZD/QTSS）。

#### B4. 两套互相矛盾的辅助分型实现并存
- **路径 A（主流程）**：`apply_auxiliary_typing` 调用 `auxiliary_directory.py` 的 classifier，做真实拆分。
- **路径 B（Web）**：`web/app.py` L358–359 调用 `AuxiliaryDirectoryExporter().classify_records()`，该模块另写一套：
  - CCI 分级名"无合并症/一般/重要/特别重要合并症"，且 `_classify_cci` (L161–167) 把 **score≥4 一律归"特别重要合并症"**（规范 3-4=严重、≥5=极严重，冲突）；
  - 年龄分档"幼儿期1-5岁/学龄期6-11岁"（calculator 是 1-6 / 7-17，与规范"学龄前期1-6、学龄期7-17"对照 calculator 更贴合）；
  - 系数体系与路径 A 完全不同。
- **影响**：同一批数据，CLI 与 Web 给出的辅助分型结论不一致；且 exporter 依赖 `record.cci_score` / `record.severity_level` 等属性，而这些在 CLI 流程中**未被填充**，Web 端实际也读不到正确分型。
- **整改**：统一为单一数据源——保留 `auxiliary_directory.py` 的 classifier 作为唯一引擎，exporter 改为消费其输出（`AuxiliaryClassification` 由 classifier 结果构造），删除 exporter 内自有的矛盾分级。

### 🟡 中度偏差（应修正）

#### B5. 高费用判断基准错误（用了次均费用而非"分值费用标准"）
- **规范**："医疗费用不小于**该病种分值费用标准**3 倍"。
- **实现**：`classify_malignant_tumor` 的 `cost_standard` 参数，在 `AuxiliaryDirectoryCalculator` (L734) 传 `disease_avg_cost * 2`，在 `apply_auxiliary_typing._classify_members` (L1827) 传 `avg_cost`——都是**病种次均费用（或其 2 倍）**，而非 RW×点值（分值费用标准）。
- **整改**：传入真实"分值费用标准"（RW×点值），而非任意平均费用倍数。

#### B6. 未排除中医优势病种 / 床日病种
- **规范**："中医优势病种、床日病种病例不纳入辅助分型范围"。
- **实现**：`apply_auxiliary_typing` 仅排除 `group_type != CORE` 与 `excluded`，**无中医/床日排除逻辑**。
- **整改**：在 `DiseaseGroup` / 入组环节增加 `is_tcm_advantage` / `is_bed_day` 标记，触发前过滤。

#### B7. 多辅助分型规则竞争逻辑缺失
- **规范**："当病例符合多个辅助分型规则时，纳入触发系数最高的分型中计算调节系数"。
- **实现**：`_classify_members` 对每个维度独立分型，最终取 **CV 改善最大者**拆分；无"按触发系数最高竞争分流"（且触发系数本身未实现，见 B2）。
- **整改**：B2 实现后，以此为基础做多规则竞争。

#### B8（B4 子项）. exporter CCI 分级与 calculator 冲突
- 见 B4。`_classify_cci` 的 thresholds（≥4 全归特别重要 + 系数 1.3/1.4）与规范 3-4=严重 / ≥5=极严重、系数体系不符。

#### B9（B4 子项）. exporter 与 calculator 年龄分档矛盾
- 见 B4。exporter `AGE_TYPES` 用 1-5 岁幼儿 / 6-11 学龄期，与规范及 calculator 的 1-6 / 7-17 不一致。

### 🟢 轻微 / 数据依赖（需确认或低优先）

- **B10. ICU 触发未放宽**：规范"监护病房住院天数辅助分型触发条件可适当放宽"。代码对 ICU 维度用统一阈值(15/5/20%)，未放宽。
- **B11. 65 岁以上未结合严重程度校正**：规范"65 岁以上利用疾病严重程度辅助分型进行校正"。`_classify_elderly` 仅做年龄段分档给系数，未与严重程度结合。
- **B12. 儿科分档依赖 day_age 字段**：规范"0-28天/29天-1周岁"。代码对 age<1 用 `day_age` 细分，缺失时退化为"年龄<1岁"，依赖数据质量。
- **B13. 字段语义核实**：规范"治疗费（不含手术费）占比"。代码用 `treatment_cost`，需确认 `MedicalRecord.treatment_cost` 确为"不含手术费"；同理 `drug_cost` 是否即药品费。
- **B14. 上年度病例数代理**：触发条件①"上年度病例数"被 `group.case_count`（当前组病例数）代理。本地测算可接受，但应注明口径（目前阈值已参数化，OK）。

## 五、复核方法说明

1. 通读 `auxiliary_directory.py` / `auxiliary_directory_exporter.py` / `apply_auxiliary_typing` 全链路；
2. 用 pandas 解析 `CCI.xlsx`（231 行）、`中重度分型诊断.xlsx`（3684 行），程序化比对硬编码字典与权威字典的码覆盖差异（实测：CCI 漏 39 / 多 44 前缀；重度诊断字典 268 条、中度 3053 条，硬编码仅覆盖数条）；
3. 比对 `web/app.py` 调用关系，确认存在双实现路径。

> 注：用户规范文本对 Charlson 17 项仅"列举主要项"，未列全（如风湿性/偏瘫/肾病）。经 `CCI.xlsx` 确认这些本属标准 17 项，故代码"包含它们"**不算偏差**；真正问题是硬编码与权威字典的漂移，应改为加载 xlsx。
