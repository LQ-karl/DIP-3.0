## 1. 项目背景与目标

### 1.1 背景
依据《国家医疗保障按病种分值（DIP）付费 3.0 版技术规范（征求意见稿）》，各地需基于本地历史出院病例数据，测算形成**本地 DIP 目录库**（核心病种 + 综合病种），并产出病种分值（RW）、CCI 合并症指数、疾病严重程度分型等基础测算结果，支撑后续本地化付费方案制定。

### 1.2 目标（实际范围）
本系统当前目标定位为「**本地目录库测算引擎**」，聚焦以下产出：

1. ✅ 医保结算清单数据接入（Excel / CSV / 4101A 接口）。
2. ✅ 极端病例费用裁剪（离群值剔除）。
3. ✅ 核心病种与综合病种的四层成组聚类。
4. ✅ 核心病种的触发式辅助分型（拆分为独立子组）。
5. ✅ 病种分值 RW（平均费用法）测算。
6. ✅ CCI 字典、疾病严重程度字典查表与标注。
7. 🟡 本地目录库与国家目录库匹配对照（可选，传参启用）。
8. ✅ 本地目录库多视角导出（完整版 / 核心病种 / 综合病种 / 统计报告）。
9. ✅ Web 交互界面（Streamlit）。

### 1.3 明确排除范围（现状）
按既有约定，本地目录库测算**不**包含以下完整 DIP 系统能力（代码已确认未接入主管线）：
- ⚪ DIP 入组引擎（`DIPGroupingEngine.group_records`）——仅被 Web/独立工具调用，不在生成本地目录库的主流程中。
- ⚪ 点值测算（`PointValueCalculator`）、支付标准（`PaymentStandardCalculator`）——仅存在于 `dip_tool.py` 的独立模拟结算路径。
- ⚪ 医疗机构调节系数（`HospitalCoefficientCalculator`）——未进入本地目录生成管线。
- ⚪ 特例单议、年度时间权重、本地目录评分等模块——代码中已实现但未接入主管线。

## 2. 业务规范依据与术语

### 2.1 依据
- 《国家医疗保障按病种分值（DIP）付费 3.0 版技术规范（征求意见稿）》（主）
- 《医疗保障信息平台定点医药机构接口规范》4101A 接口（数据接入）
- 国家目录库《DIP 3.0 版分组征求地方意见的函》对应病种条目（4974–5024）

### 2.2 术语
| 术语 | 说明 |
|------|------|
| DIP | 按病种分值付费（Diagnosis-Intervention Packet） |
| RW | 病种分值（Related Weight），RWi = mi/M × 1000 |
| 核心病种 | 本地聚类后病例数 ≥ 临界值（默认 15）的病种组合 |
| 综合病种 | 病例数 < 临界值的病种，收敛聚类后的组合 |
| CCI | Charlson 合并症指数（Charlson Comorbidity Index） |
| CV | 变异系数（Coefficient of Variation），衡量组内费用离散度 |
| 辅助分型 | 对核心病种按严重程度/年龄/ICU/CCI 触发式细分（属成组后阶段） |
| 诊断辅助细分 | 核心病种成组的「第三层规则」（肿瘤放化疗靶向免疫、烧伤类、结核耐药），属成组阶段，与辅助分型机制不同，不可混淆 |

## 3. 系统总体架构

### 3.1 分层结构
```
src/
├── models/        数据模型（MedicalRecord / DiseaseGroup / GroupType 等）
├── core/          测算核心算法（成组引擎、RW、辅助分型、质控…）
├── interfaces/    外部接口（4101A 解析、结算清单导入）
├── database/      数据库连接器 + ORM（本地测算不依赖）
├── utils/         路径解析、数据字典加载
├── visualization/ matplotlib 图表
└── dip_tool.py    统一 API 入口（DIPGroupingTool）
web/app.py         Streamlit 前端（唯一交互界面）
scripts/           建库 / 校验 / 归档脚本
tests/            pytest 测试套件
data/             字典与目录库（xlsx）
```

### 3.2 主管线入口
`src/core/local_directory_generator.py` → `LocalDirectoryGenerator.generate_local_directory(settlement_file, national_directory_file=None, output_dir=None)`。
统一 CLI/工具入口：`src/dip_tool.py` 的 `DIPGroupingTool`。

### 3.3 路径管理
`src/utils/paths.py` 集中解析目录，支持环境变量覆盖，消除硬编码绝对路径：
- `DIP_PROJECT_ROOT` → 项目根
- `DIP_DATA_DIR` → 数据目录（默认 `项目根/data`）
- `DIP_OUTPUT_DIR` → 输出目录（默认 `项目根/output`）
- `DIP_TEMPLATES_DIR` → 模板目录（默认 `项目根/templates`）

## 4. 功能需求

### FR1 数据接入与导入  ✅
- **FR1.1** 支持读取医保结算清单 Excel（`.xlsx`）与 CSV（`.csv`）。
- **FR1.2** 读取时诊断/手术编码列以字符串（`dtype=str`）保留，避免尾随零（如 `47.0100`）被截断。
- **FR1.3** 支持 4101A 接口数据结构解析（`interfaces/parser_4101a.py`）：JSON / XML / Excel → `MedicalRecord`。
- **FR1.4** 通用结算清单导入（`interfaces/settlement_importer.py`）：含中文字段列名映射（`_map_columns` / `_map_item`），支持 Excel/CSV/XML/JSON。
- **FR1.5** Web 端支持「测试数据」一键生成（20 条心肌梗死 + 15 条阑尾炎样例）用于演示。

### FR2 极端病例费用裁剪  ✅
- **FR2.1** 对每个病种组合，按费用分位裁剪离群病例：默认下界 2.5%（`lower_quantile=0.025`）、上界 97.5%（`upper_quantile=0.975`）。
- **FR2.2** 仅当组内病例数 ≥ `min_trim_group_size`（默认 25）时才执行裁剪；小样本组不裁剪。
- **FR2.3** 整体裁剪率超过 `max_overall_trim_rate`（默认 8%）时仅告警、不阻断。
- **FR2.4** 裁剪上下限、裁剪病例数、原始病例数写入病种组合，供导出。

### FR3 核心 / 综合病种四层成组  ✅
聚类键生成顺序（命中即返回）：**①先期分组 → ②并项规则 → ③诊断辅助细分 → ④基本规则**。

- **FR3.0 测算顺序与成组层次标注（强制）**：本地目录库测算严格按上述四层顺序成组与输出。
  - 每条清单记录仅命中最高优先级的一层（`_refine_core_group_key` 依次判定 ①→②→③→④，命中即返回），得到唯一核心成组键与其**成组层次**（`grouping_layer` ∈ 先期分组/并项规则/诊断辅助细分/基本规则）。
  - 综合病种（第二阶段未达核心阈值者）层次标记为 `综合病种`。
  - 辅助分型（第三步）拆分出的子组继承父核心病种的成组层次。
  - 导出的本地目录库（`_export_full_directory` / `_export_core_directory`）与分值计算（`calculate_all_disease_values`）**严格按 `①先期 → ②并项 → ③诊断辅助细分 → ④基本规则 → 综合病种` 顺序排序**（同层内按病例数降序、病种代码升序），新增「分组层次」列明示所属层。回归用例见 `tests/test_local_directory.py::test_grouping_layer_order`。

- **FR3.1 先期分组（`_detect_priority`）**（依据《DIP3.0版分组征求地方意见的函》4956–4973 项）：
  - 器官移植：**不区分主要诊断**，依靠主/相关手术操作匹配移植术式前缀（肾 55.6/55.69、肝 50.51/50.59、心 37.51、肺 33.5、造血 41.0x 等）（函 4956–4963）。
  - 呼吸循环支持：**不区分主要诊断**，手术码前缀 `39.6`(ECMO)/`39.95`(CRRT)/`96.7`(呼吸机)/`93.9`(无创通气)/`37.6`(IABP)（函 4964–4968）。
  - 低出生体重儿：**不区分主要诊断**，依靠「天龄 ≤ 28 天（天龄/出生日期+入院时间推算）」＋「新生儿出生体重(g) < 2500」两字段判定（函 4969–4973）。
  - **国家目录库对齐**：加载 `data/DIP3.0国家目录库.xlsx` 后，低出生体重直接产出国家 DIP 编码 `P07-01`(<750g)/`P07-02`(750–999)/`P07-03`(1000–1499)/`P07-04`(1500–1999)/`P07-05`(2000–2499)，组标记 `national_matched=True`、`national_dip_code`；未加载时降级为描述性键 `PRI|LBW|新生儿期|极低出生体重`。器官移植/呼吸循环支持仍返回 `PRI|TRANSPLANT|...` / `PRI|LIFESUPPORT|...`。

- **FR3.2 并项规则（`_init_grouping_rules`）**：
  - 诊断并项：如心绞痛 `I20` 3 位码归并。
  - 手操并项（诊断维度）：如血管瘤 `D18.0` 多术式并项。
  - 手操并项（术式维度）：如肾动脉支架 `39.9016` + 球囊 `39.5002` 规范并项。
  - 🟡 外部成组规则文件 `data/dip30_grouping_rules.json` 可覆盖种子规则；当前仓库仅有 `dip30_grouping_rules.example.json`，故默认不加载，规则以代码内置为准。

- **FR3.3 诊断辅助细分（`_refine_diagnostic_auxiliary`）**——属成组层，产独立核心组：
  - ✅ 肿瘤放化疗靶向免疫：主诊断 `Z51.1`/`Z51.8` + 其他诊断限定 `C00-C75`/`C76-C80`/`C81-C86`/`C88`/`C90`/`C91-C95` 类目（**不含** C87/C89/C96/C97 及 D 类）+ 主要/相关手术操作（化疗 `99.2503` / 靶向 `99.2800x006` / 免疫 `99.2800x005` 及组合）（函 4974–5015）。**国家目录库对齐**：加载后按「主诊断 × C范围(6档) × 治疗组合(7种)」直接产出国家 DIP 编码（如 `Z51.1-23`、`Z51.8-40`）；无治疗操作或组合在国家库无对应行时降级为描述性键 `AUX|TUMOR|<肿瘤3位>|<治疗方式>`。
  - ✅ 结核耐药：主诊断 `A15-A16`/`A17`/`A18`/`A19` 类目；主诊断命中内置耐药拓展码清单（`TB_DRUG_RESISTANT_CODES`，60 码）或 次要诊断含 `U84.300` → 耐药（函 5040–5061，22 行；国家库耐药标志存于 `相关手术操作编码` 列的 是/否）。**国家目录库对齐**：加载后按「类目 × 术式组 × 耐药」直接产出国家 DIP 编码（如 `A15-A16-00`(非耐药无术式)/`A15-A16-02`(耐药无术式)/`A15-A16-12`(胸廓成形术)/`A17-02`）；未加载时降级为 `AUX|TB|<类目>|<耐药/非耐药>`。
  - ✅ 烧伤类：先区分年龄（<14 岁儿童/成人，年龄(岁)字段或 入院时间−出生日期 推算），再按 深度（主诊断 `T29.x`/`T30.x` 第4位深度码：Ⅰ/Ⅱ/Ⅲ/深Ⅱ/深Ⅲ/Ⅳ度）× 面积（次要诊断 `T31`/`T32` 第4位：<10% ~ ≥90%，缺失为「未特指面积」）→ 键 `AUX|BURN|<年龄>|<深度>|<面积>`（函 5016–5039，24 项）。⚠️ `DIP3.0国家目录库.xlsx` 为排序截断导出（止于 5023 行、缺失烧伤段），故烧伤暂无法对齐国家 DIP 编码，保持描述性键；函 PDF 为权威来源。

- **FR3.4 基本规则（兜底）**：主诊断 4 位码 + 主手术 + 相关手术（无主手术时键为 `{diag}||`）。

- **FR3.5 核心 / 综合判定**：聚类后病例数 ≥ `threshold`（默认 15）为核心病种；不足者进入综合病种池，按手术类别收敛为四子组：内科诊疗组 / 诊断性操作组 / 治疗性操作组 / 相关手术组（`MIX_{subtype}_{diag3}`）。

### FR4 触发式辅助分型  ✅（拆分，系数未参与 RW）
- **FR4.1 触发条件（三个同时满足才对某一维度触发）**：
  - 该核心病种总病例数 ≥ `min_total_cases`（默认 15）；
  - 某分型等级病例数 ≥ `min_type_cases`（默认 5）；
  - 分型后组内变异系数（CV）改善 ≥ `cv_improvement_pct`（默认 0.20，即 CV 下降 ≥20%）。
- **FR4.2 四维度（逐条分型）**：
  1. 严重程度：`DiseaseSeverityClassifier` —— 恶性肿瘤 7 亚型（死亡/高费用一/高费用二/肿瘤转移并发/功能衰竭休克脓毒症/重要器官病损感染/其他）；非恶性 4 级（死亡/重度/中度/轻度）。
  2. 年龄特征：`AgeFeatureClassifier` —— 儿科（0-28天/29天-1岁/1-6岁/7-17岁）、老年（65-69/70-79/80+岁）。
  3. ICU 天数：`ICUStayClassifier` —— <2 天不分级；2-7 / 8-14 / 15-30 / 31+ 天。
  4. CCI：`CCICalculator` —— 无(0) / 一般(1-2) / 严重(3-4) / 极严重(≥5)。
- **FR4.3 拆分逻辑**：取 CV 改善最大的维度，按等级建子组；低频等级（<`min_type_cases`）并入「其他(低频)」；子组代码 `{父code}_{维度}_{等级}`。综合病种不拆分。
- **FR4.4 系数**：各维度分级设默认拟合系数（CCI 无1.0/一般1.1/严重1.2/极严重1.3；恶性死亡1.5…；年龄 0-28天1.25…80+1.2；ICU 2-7天1.15…31+1.7 等），**均为可配置默认值**。
  - ⚠️ **现状差异**：`auxiliary_coefficient` 字段虽被赋值，但 RW 计算仍用 `avg_cost` 直接算，**系数未乘入 RW**——当前仅用于「拆分」，不参与分值调节。需求需明确是否要系数调节（见第 11 章待决问题）。

### FR5 病种分值 RW 测算  ✅
- **FR5.1 公式（平均费用法，管线默认且当前唯一启用）**：
  `RWi = mi / M × 1000`
  - `mi`：第 i 类病种组合的次均费用（裁剪后有效病例加权）；
  - `M`：本地所有出院病例的平均住院费用（以裁剪后有效病例数为权重）。
- **FR5.2** 另已实现但未在主管线启用的方法（代码层 `ValueCalculator`）：基准病种费用法（`RWi = mi / 基准病种费用 × 1000`）、标准定额法（`RWi = mi / M`，不乘 1000）。
- **FR5.3** 药品/耗材分值（`dRWi = dmi/dM`、`cRWi = cmi/cM`）在 `ValueCalculator` 中定义，Web 结果页有展示字段，但本地目录生成主流程未单独产出。

### FR6 字典查表与标注  ✅
- **FR6.1 CCI 字典**（`data/CCI.xlsx`）：`_load_cci_dictionary` + `_compute_group_cci`，写入病种组合 `cci_score`。
- **FR6.2 疾病严重程度字典**（`data/中重度分型诊断.xlsx`）：按真实诊断码（`ASSI_ITEM_ID`）匹配 `DIP_ASSISTANT_NAME`/`DIP_ASSISTANT_TYPE`，写入 `severity_level` / `severity_type`。
- **FR6.3 手术操作类别映射**（`data/（2）手术操作分类代码国家临床版3.0（2022汇总版）.xlsx`、`ICD9国临版3.0对照医保版2.0_0125.xlsx`、`新增医保手术操作代码.xlsx`）：国临版码→类别（手术/治疗性操作/诊断性操作/介入治疗），支撑综合病种四子组与类别标注。

### FR7 国家目录匹配（可选）  🟡
- **FR7.1** 传入 `national_directory_file` 时加载 `DIP3.0国家目录库.xlsx`，按「主要诊断 4 位码 + 主要手术操作编码」匹配本地病种，写入 `national_dip_code` / `national_matched`，并导出《与国家目录库匹配结果.xlsx》。

## 5. 关键算法与公式汇总

| 项目 | 公式 / 规则 | 现状 |
|------|-------------|------|
| 极端裁剪 | 组内费用 2.5%–97.5% 分位，组样本 ≥25 才裁，整体 ≤8% | ✅ |
| 核心病种阈值 | 病例数 ≥ 15 | ✅（可配） |

| CCI 分级 | 无(0)/一般(1-2)/严重(3-4)/极严重(≥5) | ✅ |
| 严重程度 | 恶性 7 亚型 / 非恶性 4 级 | ✅ |
| 点值 / 支付标准 | 见 `payment_calculator`（独立路径） | ⚪ 未接入本地管线 |
| 医院系数 | 基本 + 加成 | ⚪ 未接入本地管线 |

## 11. 现状差异与待决问题

> 本章是「反推文档」最有价值的部分：列出代码现实与规范/既有文档的偏差，供后续开发决策。

1. **Web 与本地目录管线口径不一致**：Web「分组测算」用国家目录匹配成组 + 医院系数 + 点值；`generate_local_directory` 用本地聚类、不做点值/医院系数。两者结果不可对齐。**待决**：统一为同一套成组与测算口径，或明确 Web 为「演示/对照」用途。
2. **辅助分型系数未乘入 RW**：`auxiliary_coefficient` 仅用于拆分，不参与分值。**待决**：是否需要让系数调节 RW（涉及支付方案，需业务确认）。
3. ~~**③ 诊断辅助细分 — 烧伤类缺失**~~：**已实现（2026-07-27 补充）**。按用户提供的《函》补充逻辑落地：年龄（<14 儿童/成人）× 深度（T29/T30 第4位）× 面积（次要诊断 T31/T32 第4位）。同批修订：低出生体重儿改为「不足1周岁 + 出生体重<2500g」（不看 P07 诊断）、呼吸循环支持取消 G47.3 诊断排除、肿瘤其他诊断收窄至 C00-C75/C76-C80/C81-C86/C88/C90/C91-C95、结核耐药拓展码内置 60 码清单。
4. **低标目录未接入**：`load_low_standard_directory` 已定义但主管线未引用。
5. **外部成组规则未生效**：代码只认 `dip30_grouping_rules.json`，仓库仅有 `.example` 版本，默认走内置种子规则。
6. **CI 尚不绿**：`ci.yml` 注释自述——data/ 关键字典与 `tests/sample_settlement_data.xlsx` 未纳入版本控制；代码/测试仍残留部分硬编码 `F:\DIP` 绝对路径（paths.py 已覆盖核心，但未全量应用）。
7. **`load_assistant_classification`（辅助分型AI参考.xlsx）定义但零调用**，疑似遗留。
8. **`grouping_engine` 与本地目录先期分组两套实现**：Web 用 `DIPGroupingEngine.classify_advanced_group`，本地目录用 `LocalDirectoryGenerator._detect_priority`，存在重复与潜在分歧。
9. **质控剔除默认关闭**：与规范「可予以剔除」留口，默认保留低阈值综合病种。
